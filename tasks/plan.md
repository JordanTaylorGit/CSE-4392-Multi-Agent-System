# P2 LangGraph orchestrator

## Objective and scope

Implement the existing assignment pipeline in LangGraph while retaining the team's skill files as the stage prompts.
Loc authorized the full P2 orchestrator and an injected, replaceable model on November 16, 2026.
Loc requested Ollama; the selected default is the local qwen3-coder:30b model.
The graph receives its model and build runner as dependencies; tests supply deterministic substitutes.

## Design

The graph owns sequencing, concurrent EP/BVA generation, joining, human review, bounded retries, and completion.
Miguel's helpers remain responsible for merging cases, checking G1 evidence, and generating the initial JUnit suite.
Model calls handle generation, source repair, refactoring, and additional coverage tests.
Original approved tests are reused unchanged against the refactored source through the Maven profile.
If preserving those tests requires a compatibility change, the refactoring stage must provide it; the runner does not silently weaken assertions.
All edits and builds occur in a per-run workspace copied from the repository.
SQLite checkpoints are authoritative; STATE.md and reports are projections for people.
Human decisions are bound to the reviewed artifact hash and are never generated by a model.
Coverage requires real passing tests, nonempty reports, and zero missed branches for the configured 100% gate.
The coverage scope is explicitly reported and follows P3's exclusion of main().

## Structure and commands

`harness/` contains model construction, stage execution, build integration, graph, and CLI.
`tests/` contains model substitution, gate/resume, retry, output-validation, and Java integration tests.
`docs/ARCH.md`, `docs/CONTRACTS.md`, and the orchestrator skill document the implemented behavior.
`docs/activity.drawio` and `docs/activity.png` show the same control flow.

```bash
uv sync --locked
uv run pytest -q tests .agents/testgen/tests
uv run ruff check harness tests
uv run python scripts/validate_skills.py
uv run python -m harness start --project seasonswitch
uv run python -m harness status --run runs/<run-id>
uv run python -m harness resume --run runs/<run-id> --decision decision.json
```

## Ordered slices

1. Model boundary and run files: verify injected fake models, JSON validation, and allowed output paths.
2. Graph and human gates: verify parallel join, real interrupts, durable resume, rejection loops, and five-attempt limits.
3. Java integration: verify P4 helpers, passing/failing Maven executions, trustworthy coverage, and unchanged test reuse.
4. CLI, diagrams, documentation, and CI: verify a complete deterministic run, inspect the rendered diagram, and run the full suite.

## Boundaries and limitations

Do not edit teammates' prompts or project vocabulary to conceal integration gaps.
Do not push, submit the assignment, or fabricate human approvals or model-run evidence.
Never execute a model-provided command or let a model write outside approved Java directories.
Generated Java is executable code; a copied workspace is isolation from repository edits, not an operating-system sandbox.
The build runner strips API credentials from the child environment and has a timeout.
A live model run requires Ollama with the selected model installed and real G1/G3 reviewers.
